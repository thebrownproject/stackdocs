# Product Naming — open decision (revisit later)

**Status:** Parked — 2026-05-29. Decision owner: Fraser.

## Current call

**Public-facing brand = "Stackdocs"** (for now).

- Customer-facing surfaces use **Stackdocs**: the landing page
  (`frontend/app/page.tsx`), the GTM outreach playbook, and the `stackdocs.io`
  domain.
- **"Trestle"** remains an **internal codename** for the rebuilt product line and
  still appears in engineering docs and identifiers — intentionally left as-is for
  now (not worth a churny rename):
  - `docs/specs/TRESTLE-ARCHITECTURE.md`
  - `README.md` (titled "Trestle"), `frontend/CLAUDE.md`
  - the "Trestle" design-token comments in `frontend/app/globals.css`
  - the GTM build spec `docs/superpowers/specs/2026-05-28-trestle-gtm-tier-1-and-2-design.md`

## Why parked

"Trestle" may be a stronger long-term name (cleaner, brandable, not tied to the
literal "stack of docs" framing). But renaming now is premature: there are no
customers yet, the domain is `stackdocs.io`, and a rename touches many surfaces.
Keep momentum on GTM; decide the name deliberately later.

## To revisit when we come back

- [ ] Trademark / domain availability for "Trestle" (.com, .io, .ai).
- [ ] Does "Trestle" communicate the product to construction/PM buyers, or is it
      too abstract vs. the descriptive "Stackdocs"?
- [ ] Cost of a full rename: landing + playbook + README + architecture docs +
      design-token labels + any in-app brand strings + domain/email + social.
- [ ] Option floated: **"Trestle by Stackdocs"** (product under company/domain) as
      a low-commitment middle path.
- [ ] Decision: commit to one name and do a single sweeping rename, or keep the
      Stackdocs-brand / Trestle-codename split permanently.
